# v3.2.1 — Bounded Cosine MAP + Sub-linear sCRP count

CLI method: `hi-ontop-full-v3.2.1`. Segmenter class: `HiOnTopSegmenterV32`.

## 한 줄

v3.1.1 의 likelihood 그대로. **sticky-CRP prior 의 count 항 만 `C_k → (C_k+1)^β` 로 squashing** (β < 1).

## v3.1.1 대비 변경

| 축 | v3.1.1 | v3.2.1 |
|---|---|---|
| sticky-CRP count | `C_k` (raw) | `(C_k + 1)^β`, β ∈ (0, 1] |
| likelihood | `τ · cos(s, μ_k)` | 동일 |
| topic state | centroid `μ_k` only | 동일 |
| new cluster score | `τ · cos_threshold` | 동일 |

식에서 변경된 곳은 `sticky_crp_unnormed()` 한 줄. `β=1.0` 이면 v3.1.1 과 정확히 일치.

## Score 식

```
ê_n = argmax_k [ log[ (C_k + 1)^β + λ · 𝟙[e_{n-1}=k] ]  +  τ · cos(s, μ_k) ]
```

prior 에서 `C_k` 가 직접 곱해지지 않고 `(C_k+1)^β` 로 들어감. β=0.5 면 sqrt, β=0.25 면 더 강하게 압축.

## 동기 (mega-topic 직접 해결)

v3.1.1 의 가장 큰 잔존 문제: 한 번 커진 topic 의 prior 가 비례적으로 커져 다음 turn 도 흡수, 또 커지고… 양의 피드백.

**Diagnostic** (decision-log 인용 / `sem_core_optimize_pe.py` docstring):
- `C_k ~ 600, α = 10, τ = 50, cos_threshold = 0.3` 인 긴 대화 환경에서 raw v3.1 은 `cos(s, μ_k) > 0.218` 만 되어도 기존 topic 이 새 cluster 를 이김. 거의 항상 통과.
- `β = 0.5` 면 그 임계점이 ~0.275 로 올라감. `β = 0.25` 면 ~0.292.
- 즉 sub-linear count 는 *진짜 의미적 shift* 가 일어나야 새 topic 이 열리도록 강제.

→ likelihood 식이 아니라 **prior 식 한 곳** 에 손대서 mega-topic 을 직접 친다.

## 폐기된 v3.2 (cosine PE + AR(1) ρ)

원래 v3.2 는 *prediction-error* 측이었음 (centroid 대신 AR(1) blend `ρ μ + (1−ρ) s_last` 로 다음 embedding 예측). 그러나:
- mega-topic 의 *주원인* 인 prior 폭주를 해결 못 함.
- hyperparameter `ρ` 만 추가되고 empirical payoff 부족.

→ 폐기. 현재 살아있는 v3.2 라인은 v3.2.1 (sub-linear count) 단독. AR(1) PE 변형은 `sem_core_optimize_pe.py` 라는 *원래 v3.2 PE 용 파일명* 만 남고, 내부는 v3.2.1.

자세한 migration note: `context/06-decision-log.md`.

## SEM 계승 측면

- ✅ sticky-CRP prior 의 *형태* 는 SEM Eq.1 그대로 (`C_k` 항 + `λ · stick` 항 + `α` 새 cluster).
- ⚠️ `(C_k+1)^β` 는 **SEM 에 없는 modification**. 단 SEM 에 *없는 것을 새로 추가*한 게 아니라 *있는 것을 누그러뜨린* 것 → SEM 계승 원칙(`CLAUDE.md`) 위반은 아니라고 판단.
- 정당화 근거: SEM 식의 raw count 가 conversation segmentation 에선 mega-topic 을 유발하며, 이는 SEM2 가 다룬 video event 와 달리 conversation 의 token-rate / topic-revisit 패턴 때문에 노출되는 *환경 mismatch*. SEM 본 정신을 보존하면서 해당 mismatch 만 절단.

## 알려진 한계

1. **likelihood 측면은 v3.1.1 그대로** → cosine surrogate 로서의 한계 (τ calibration, cos_threshold global 고정, centroid-only) 는 모두 잔존.
2. **β 도 hyperparameter**. β=1.0 vs 0.5 vs 0.25 비교 sweep 필요.
3. **prior–likelihood 균형**: β 를 줄이면 prior 가 약해지고 cosine likelihood 가 상대적으로 강해짐. τ 와 함께 jointly 튜닝.

## Deprecation 상태 (2026-05-09)

**상위 라인**: v3.3.x (`v3.3.1` → `v3.3.2` → `v3.3.3`/`v3.3.4`) 가 v3.2.1 의 sub-linear sCRP prior 를 **그대로 상속** + likelihood 단을 RNN prediction 으로 교체. 즉 v3.2.1 는 v3.3.x 가 SEM 본진의 scene dynamics 를 추가하기 *이전 단계 baseline*.

새 sweep / ablation 의 주력은 v3.3.2 / v3.3.3 / v3.3.4. v3.2.1 은:
- **이론적 ablation** (RNN dynamics 빼면 acc 가 어떻게 떨어지는가) 에는 여전히 유효.
- **production 후보** 로는 v3.3.x 에 밀림.

코드 / CLI 분기 모두 유지 중 (`hi-ontop-full-v3.2.1`). 의도적으로 제거하지 않음.
