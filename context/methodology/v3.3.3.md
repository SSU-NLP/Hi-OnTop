# v3.3.3 — f0 / repeat-vs-restart 복원

CLI method: `hi-ontop-full-v3.3.3`. Segmenter class: `HiOnTopSegmenterV333` (구현 2026-05-09).

## 한 줄

v3.3.2 의 cosine+shared-GRU PE 구조 위에 SEM2 `log_likelihood_f0` 의 **같은 event label 재시작** 분기를 복원한다. 핵심 변화는 $k_{\text{prev}} = k$ 인 경우를 단일 repeat score 로 보지 않고, `repeat` 와 `restart` 두 경로로 나누어 boundary 여부까지 결정하는 것이다.

## SEM2 원래 동작

SEM2 `run()` 은 직전 event $k_{\text{prev}}$ 에 대해 두 likelihood 를 동시에 계산한다.

- repeat: `log_likelihood_next(x_prev, x_curr)` — 직전 event dynamics 가 다음 scene 을 예측한 경우.
- restart: `log_likelihood_f0(x_curr)` — label 은 같은 event $k_{\text{prev}}$ 이지만 새 token / 새 episode 시작 상태에서 현재 scene 이 나온 경우.

SEM2 의 posterior 구성은 다음 형태다.

- repeat score: $\log(C_k+\lambda) + \log p_{\text{next},k}(x_n \mid x_{n-1})$
- restart score: $\log(C_k) + \log p_{f0,k}(x_n)$
- 같은 label posterior 는 두 경로를 합쳐 $k$ 로 유지할 수 있지만, boundary 판정은 $restart > repeat$ 이면 true 로 둔다.

즉 SEM2 에서 "같은 label" 과 "같은 episode 가 이어짐" 은 동일하지 않다. $k_n = k_{n-1}$ 이어도 restart 경로가 이기면 event boundary 다. v1 / v3.1.1 / v3.3.1 은 이 분기를 cold-start centroid fallback 으로 우회했고, v3.3.3 은 그 미포팅 항목을 복원한다.

## Hi-OnTop 식별 신호

Hi-OnTop v3.3.2 환경에서는 입력이 normalized embedding 이고 likelihood 가 cosine PE 로 바뀌어 있다. 따라서 restart 신호는 다음 조합으로 해석한다.

- $k_{\text{prev}} = k$: 같은 topic label 후보가 계속 이길 수 있음.
- repeat PE 가 큼: $\mathrm{PE}^{\text{repeat}}_{n,k} = 1 - \cos(s_n, \hat{s}_{n,k})$ 가 임계치 초과.
- f0 / restart score 가 repeat score 보다 큼: 현재 turn 이 그 event 의 "다음 장면" 보다는 "처음 장면" 쪽에 더 가까움.

대표 규칙은 $k=k_{\text{prev}}$ 에서 $\mathrm{PE}^{\text{repeat}}_{n,k} > \theta_{\text{restart}}$ 이고 restart score 가 repeat score 보다 크면 같은 topic 으로 assign 하되 boundary 를 true 로 반환하는 것이다. 이때 새 topic 을 만들지 않는 점이 v3.3.2 hard PE boundary 와 다르다.

## Score 식

기존 topic $k \le K$ 의 base prior 는 v3.3.2 와 동일하게 sub-linear sCRP 를 쓴다.

$\pi_k^{\text{base}} = (C_k+1)^\beta + \lambda \mathbb{1}[k=k_{\text{prev}}]$

$k \ne k_{\text{prev}}$ 인 경우는 v3.3.2 와 동일하다.

$S_k = \log \pi_k^{\text{base}} + \tau \cos(s_n, \hat{s}_{n,k})$

$k = k_{\text{prev}}$ 인 경우만 두 분기를 둔다.

$S_k^{\text{repeat}} = \log((C_k+1)^\beta + \lambda) + \tau \cos(s_n, \hat{s}_{n,k})$

$S_k^{\text{restart}} = \log((C_k+1)^\beta) + \tau_{f0} \cos(s_n, f0_k)$

$S_k = \max(S_k^{\text{repeat}}, S_k^{\text{restart}})$

boundary 판정:

- $k^\* \ne k_{\text{prev}}$ 이면 boundary.
- $k^\* = k_{\text{prev}}$ 이고 $S_k^{\text{restart}} > S_k^{\text{repeat}} + m_{\text{restart}}$ 이면 boundary.
- 그 외 repeat.

새 topic 점수는 v3.3.2 를 유지한다.

$S_{K+1} = \log \alpha + \tau \cdot \text{cos\_threshold}$

`f0_k` 는 우선 해당 topic 의 episode-start centroid 로 둔다. boundary 로 시작한 turn 들의 normalized 평균을 유지하며, cold-start 에서는 topic centroid $\mu_k$ 또는 current cached prediction fallback 을 사용한다.

## Hyperparameter

v3.3.2 best HP 위에서 점진 확장한다.

| 이름 | default | 의미 |
|---|---:|---|
| `cos_threshold` | 0.9 | v3.3.2 best 기반 fresh topic cosine baseline |
| `alpha` | 100.0 | v3.3.1 HP sweep best 기반 새 topic prior |
| `beta` | 0.25 | v3.3.1 HP sweep best 기반 sub-linear count exponent |
| `pe_threshold` | 0.5 | v3.3.2 best 기반 hard PE boundary |
| `rnn_train_steps` | 3 | v3.3.2 best 기반 online RNN update steps |
| `restart_pe_threshold` | 0.5 | repeat PE 가 이 값보다 클 때 restart 후보를 적극 허용 |
| `restart_margin` | 0.0 | restart 가 repeat 를 이겨야 하는 최소 score margin |
| `f0_tau` | `tau` | f0 cosine likelihood scale. 기본은 repeat likelihood 와 동일 |
| `f0_min_starts` | 2 | f0 centroid 를 신뢰하기 전 최소 episode-start sample 수 |

`restart_pe_threshold` 는 guard 다. SEM2 에서는 Gaussian likelihood 자체가 restart/repeat 를 비교하지만, cosine surrogate 에서는 repeat prediction 이 충분히 좋을 때 f0 centroid 가 우연히 이기는 것을 막기 위해 둔다.

## SEM 계승 정당화

이 버전은 새 메커니즘 도입이 아니라 SEM2 미포팅 항목의 복원이다.

1. **SEM 에 왜 있나**: SEM2 `run()` 은 직전 event 에 대해 `log_likelihood_next` 와 `log_likelihood_f0` 를 모두 계산하고, 같은 label 의 restart 를 boundary 로 취급한다.
2. **Hi-OnTop 에 왜 없었나**: v1 / v3.1.1 / v3.3.1 은 f0 를 별도 상태로 유지하지 않고 cold-start centroid / fresh cluster score 로 단순화했다. 이는 구현 단순화를 위한 미포팅이지, SEM 철학과 충돌해서 제거한 것이 아니다.
3. **충돌 없음**: sticky-CRP, local MAP, online update, scene dynamics 를 유지한다. 달라지는 것은 $k_{\text{prev}}$ 후보의 내부 경로를 SEM2 처럼 repeat/restart 로 분해하는 것뿐이다.
4. **decision-log 근거**: `context/06-decision-log.md` 2026-05-09 v3.3.3 entry.

**판정**: default HP (`restart_pe_threshold=0.5`, `restart_margin=0.0`) 에서 **same-label restart 분기는 거의 영향 없음**. segmentation 통계가 v3.3.2 와 사실상 동일 (n_topics, T1μ, T1max 모두 같은 범위) → restart 분기가 거의 발화 안 함. 가능한 원인:

1. `restart_pe_threshold=0.5` 가 너무 엄격 — repeat PE 가 0.5 이하면 restart 후보 자체를 안 봄.
2. cosine surrogate 환경에서 f0 centroid score 가 RNN repeat prediction 을 거의 못 이김 (RNN 이 초기에 centroid 와 비슷한 예측 만들기 때문).
3. `restart_margin=0.0` 도 보수적 — restart 가 repeat 보다 ε 만큼만 커도 boundary 로 가야 하는데 noise 에 묻힘.

**다음 검증 sweep 권장**: `restart_pe_threshold ∈ {0.2, 0.3, 0.4}` × `restart_margin ∈ {-5, -2, 0}` (음수 → restart 가 잠재적으로 더 자주 이김). boundary 발화 횟수 / restart 분기 승률 logging 도 추가해야 함.

## 알려진 한계

1. **f0 centroid 의 의미가 약함**: 대화 topic 은 "시작 장면" 이 영상 event 만큼 안정적이지 않을 수 있다.
2. **same-label restart 의 평가 신호 부족**: topic label ground truth 가 없으므로 repeat-vs-restart 는 segmentation 통계로 간접 평가해야 한다.
3. **v3.3.2 hard PE 와 역할 중복**: 큰 PE 에 대해 v3.3.2 는 새 topic 을 만들고, v3.3.3 은 같은 topic restart 를 허용한다. 둘의 우선순위가 성능을 좌우한다.
4. **online irreversible update**: restart 판단 후 f0 centroid 를 업데이트하면 초반 오판을 되돌리기 어렵다.
5. **(2026-05-09 관측)** default HP 에서 restart 분기 불활성: 위 sweep 결과 + 다음 검증 권장 참조.

## 고려 중인 변형

1. **global f0 fallback**: topic별 f0 sample 이 부족할 때 전체 episode-start centroid $f0_{\text{global}}$ 사용.
2. **restart-only boundary mode**: $k_{\text{prev}}$ 에 대해서만 hard PE 를 새 topic 강제가 아니라 restart 후보로 먼저 보냄.
3. **margin sweep**: `restart_margin ∈ {0.0, 1.0, 2.5, 5.0}` 로 우연한 f0 승리를 억제.
4. **f0 를 centroid 대신 first-turn RNN hidden reset state 로 표현**: SEM2 `new_token()` 에 더 가깝지만 구현 복잡도가 올라가므로 v3.3.3 기본안에서는 제외.
