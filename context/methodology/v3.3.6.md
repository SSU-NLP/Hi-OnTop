# v3.3.6 — SEM2-faithful event dynamics (persistence + history replay) + 재현성

CLI method: `hi-ontop-full-v3.3.6`. Segmenter `HiOnTopSegmenterV336` (`src/hi_ontop/sem_core_v336.py`), topic `TopicV336` (`src/hi_ontop/topic_v336.py`). 구현 2026-05-17. 단위테스트 `tests/test_sem_core_v336.py` (7).

## 한 줄

v3.3.5 의 likelihood 항(f_is_trained gating + variance + f0/restart)을 모두 유지하고, **topic dynamics 만** SEM2 충실하게 교체: (1) untrained 예측 = identity/persistence(직전 임베딩), centroid fallback 제거 (2) per-topic 독립 모델(공유 가중치 간섭 제거) (3) topic history 전체 replay 학습(`n_epochs`) (4) `rnn_ready` 를 `f_is_trained` 와 분리. 추가로 EventRNN **결정적 seed** 도입(재현성).

## 동기 (3턴 천장 + 재현성 결함)

v3.3.5 idx374 트레이스: topic 이 trained(transition_count≥1) 되는 순간 예측기가 centroid→공유 EventRNN 으로 전환되는데 그 RNN 예측 cos≈0.03~0.5(거의 랜덤) → repeat likelihood 파국 → f0-restart 가 딱 1턴 더 살리고 새 topic. 모든 topic 이 기계적 3턴 사이클(시작1 + untrained λ-유예1 + f0-restart 1). 원인 = 공유 EventRNN 의 단발 3-step·1~2예시 학습 + cross-topic 가중치 간섭(미학습).

SEM2 대조: untrained `predict_next` = identity(직전 입력 = persistence), 랜덤 RNN 아님. `estimate()` 는 training_pairs *전체* batch replay(`n_epochs`). 각 event 가 weight snapshot 으로 사실상 격리. Hi-OnTop 의 "min_history 후 centroid→공유RNN" 은 SEM2 부재 hack.

또한 EventRNN 이 unseeded → idx374 inspect 2회 실행이 9 vs 6 topic 으로 불일치(앞선 v3.3.4 REPORT 수치 불일치의 정체). CLAUDE.md "모든 randomness seed 고정" 위반.

## state / dynamics (`TopicV336`)

| 필드 | 의미 |
|---|---|
| `model`,`optimizer` | **per-topic** EventRNN+Adam (공유 아님 → 간섭 0) |
| `_seq` | 이 topic 의 관측 임베딩 순열 (replay/persistence 용) |
| `_cached_pred` | RNN 다음 예측 캐시 (update 시 갱신) |
| `seed` | per-topic 결정적 init: snapshot→`manual_seed(seed·100003+topic_id)`→build→restore |

예측: `n==0`→0; `not rnn_ready`→persistence(`_seq[-1]`); else→`_cached_pred`(RNN).
학습(update): `_seq` append → 최근 `max_history` 구간 GRU 순차 roll, 각 (i→i+1) cosine loss, `n_epochs` epoch → cache 갱신. 결정적(드롭아웃 없음, full-seq).

## 수식 (likelihood 는 v3.3.5 동일, 예측기만 변경)

`PE_k(s) = 1 - cos(predict_next_k(use_rnn), s)`,  `use_rnn := rnn_ready_k`.

`f_trained_k := transition_count_k ≥ min_transitions_for_pe` (likelihood gate, v3.3.5).
`rnn_ready_k := transition_count_k ≥ rnn_ready_min_transitions` (예측기 gate, **신규·분리**).

trained 이나 not rnn_ready → persistence 예측으로 PE 계산(여전히 v3.3.4 `−PE²/2σ_k²`). rnn_ready 후에만 RNN.

## HP default

| 이름 | default | 의미 |
|---|---:|---|
| `rnn_n_epochs` | 10 | topic history replay epoch (SEM2 estimate 기본) |
| `rnn_ready_min_transitions` | 3 | RNN 사용 전 최소 transition (persistence→RNN) |
| `rnn_max_history` | 64 | replay 구간 상한 (O(H·E) 제한) |
| `seed` | 0 | per-topic 결정적 init |
| (v3.3.5 계승) `min_transitions_for_pe` | 1 | f_is_trained gate |

`rnn_min_history` 등 v3.3.x legacy HP 는 시그니처 호환용으로 받되 미사용.

## SEM 계승 정당화

- **왜 SEM2 에 없나**: SEM2 는 untrained=identity/persistence, trained=history batch replay. Hi-OnTop 의 centroid fallback·단발 SGD·공유모델은 미구현/단순화. v3.3.6 은 **SEM2 복원** → 3-step 부담 낮음(predictor semantics 변경이라 별 버전 분리).
- **충돌 없는가**: sCRP/Bayes/local MAP·f_is_trained gating·f0/restart 와 무충돌. cosine replay loss 는 event model 내부 학습 목적함수.

## 알려진 한계 / 검증 미해결

1. **경계 *위치* 품질 미해결**: 분절 양은 줄었으나 #14|#15(같은 "습관" 연속) 가 여전히 분절. 원인은 dynamics 아니라 likelihood/fresh-baseline calibration → v3.3.7/8 진단.
2. per-topic 모델 = 메모리/시간 비용 증가(topic 수 × 작은 GRU). 표본 짧아 실측 부담은 작으나 대화 길면 점검 필요.
3. persistence 예측은 "같은 주제라도 하위질문 이동" 턴에 cos~0.4 → PE~0.6 (v3.3.7/8 진단 대상).
