## 알고리즘 (수학 정의)

각 turn t 에서 두 encoder 의 인접·causal-window cosine PE 계산:

```
topic 채널 (mpnet):
  δ_prev_topic(t) = 1 − cos(s_topic[t-1], s_topic[t])
  c_topic[t-1]    = Σ_{i=1..m_topic} ρ_topic^{i-1} · s_topic[t-i]
  δ_ctx_topic(t)  = 1 − cos(c_topic[t-1], s_topic[t])
  δ_topic(t)      = a_topic · δ_prev_topic + (1 − a_topic) · δ_ctx_topic

flow 채널 (DSE-BERT):
  δ_prev_flow(t)  = 1 − cos(s_flow[t-1], s_flow[t])
  c_flow[t-1]     = Σ_{i=1..m_flow} ρ_flow^{i-1} · s_flow[t-i]
  δ_ctx_flow(t)   = 1 − cos(c_flow[t-1], s_flow[t])
  δ_flow(t)       = a_flow · δ_prev_flow + (1 − a_flow) · δ_ctx_flow
```

각각 채널의 train-calibrated boundary 임계값 `δ*_topic`, `δ*_flow`
로 나눠서 **threshold-normalized ratio** 산출:

```
z_topic = δ_topic / δ*_topic
z_flow  = δ_flow  / δ*_flow
```

⚠ "z-score" 라는 표현은 정통 통계의 `(x − μ) / σ` 와 다름 (centering
없음, scaling only). 본 문서는 일관되게 **"threshold-normalized
ratio"** 또는 **"calibrated normalization"** 으로 부른다. codex
권고에서 loose 하게 "calibrated z-score" 라 부른 부분 있으나 같은 양.

두 ratio 를 energy 결합:

```
r = √( w_topic · z_topic² + w_flow · z_flow² )
boundary ⇔ r ≥ 1
```

기하적으로 가중 ℓ² norm. 두 채널이 모두 ratio = 1 (각자 boundary
직전) 이면 r = 1 → boundary 직전. 한 채널만 강하면 그 채널 단독으로
boundary 결정 가능 (다른 채널이 noise level 이라도).

## v4.1.1 머신러리 보존 — internal trick

v4.1.1 의 likelihood 는 `L(δ) = −δ²/(2σδ²)` 이고 boundary 결정은
`δ_eff < δ*` 의 hard cut (prior-corrected B0 동치).

v4.2.3 은 **`r` 을 `δ_eff` 자리에 두고 내부 `δ*_internal = 1.0` 으로
강제** → V411 의 sCRP / Bayes / local-MAP / prior-corrected B0 모두
변경 없이 그대로 작동.

수치 검증 (likelihood at boundary 일치):
- v4.1.1: `L(δ = 0.5594) = −0.5594² / (2 · 0.0625 · 0.5594²) = −8.0`
- v4.2.3: `L(r = 1) = −1² / (2 · 0.0625) = −8.0`

→ σδ² 가 δ*² 에 비례 (`σδ² = sigma_delta_c · δ*²`, `sigma_delta_c =
0.0625`) 한 덕에 normalize 가 정확히 통과. softness ratio 보존.

## State 관리 (parent state vs child state)

V411 (parent) 는 단일 channel `_prev_s` / `_recent` 만 가정. v4.2.3
은 **두 채널 buffer 분리**:

| buffer | 채널 | 관리 |
|---|---|---|
| `_prev_s` | topic (mpnet) | V411 (`super().assign(s_topic)`) |
| `_recent` (≤ m_topic) | topic | V411 |
| `_prev_s_flow` | flow (DSE) | V423 (자식, `assign_pair` 끝에서) |
| `_recent_flow` (≤ m_flow) | flow | V423 |

`assign_pair(s_topic, s_flow)` 흐름:
1. `_combined_r(s_topic, s_flow)` — 두 채널 δ_adj 계산 → z → r
2. `self._cached_r = r` 저장
3. `super().assign(s_topic)` 호출 — V411 의 sCRP / MAP 진행
4. V411 가 `self._delta_eff(k, s)` 호출 (override) → cached r 반환
5. V411 가 `_prev_s` / `_recent` 갱신 (topic 채널)
6. V423 가 `_prev_s_flow` / `_recent_flow` 갱신 (flow 채널)

topic 채널이 V411 의 모든 state (sCRP counts, f0 centroids, restart
state, transition counts, σ² samples 등) 를 주도. flow 채널은 **r 계산
에만 기여**. topic identity 는 mpnet 이 결정 (smoke 정량 근거).

## SEM 계승 3-step (CONDITIONAL PASS — codex 2026-05-20)

1. **SEM2 에 있나?**
   - `LinearEvent` 의 dynamics 는 단일 representation space 의 residual
     vector 의 Gaussian log-likelihood (`x_pred - x_obs`).
   - multi-view dual encoder PE 는 SEM2 에 직접 대응 없음.
   - 다만 SEM2 likelihood 는 본질적으로 residual energy 의 1-D scalar
     로 reduce 되는 구조. v4.2.3 의 `r` 도 두 channel residual 의
     calibrated energy 의 1-D scalar.
2. **충돌?**
   - sCRP / Bayes / local-MAP / prior-corrected B0 무변경 (위 internal
     trick 으로 likelihood 등가 보존).
   - prior 항 무관, likelihood 만 "single feature → calibrated
     two-feature" 로 확장. 이 reduction 이 SEM2 정신과 호환.
3. **결론**: PASS 단 조건부 — framing 을 *"새 dynamics 도입"* 이
   아닌 *"SEM2 residual likelihood 를 calibrated two-feature PE 로
   축약"* 으로 유지해야 함. Zacks 2007 EST 의 multi-feature PE 는
   *개념적* 연결로만 사용 (성능 근거로 인용 금지).

## 결과

### 1) 단일 trial smoke (`2026-05-20_v423_smoke`)

w_topic=0.75 / w_flow=0.25 (codex 사전 권고), TIAGE-train HP 각 채널:

| arm | TIAGE | Dialseg711 | SuperDialseg | mean |
|---|---:|---:|---:|---:|
| v4.1.1 (mpnet) | 0.4675 | **0.5897** | **0.4631** | **0.5068** |
| v4.2.2 (DSE-BERT) | 0.4747 | 0.4547 | 0.3886 | 0.4393 |
| **v4.2.3-exp dual (0.75/0.25)** | **0.4904** | 0.5666 | 0.4330 | 0.4967 |

**관찰**: TIAGE 에서만 dual 이 best (+2.29pp vs mpnet). Dialseg711 / SuperDialseg
에서 dual 이 mpnet 단독에 못 미침.

### 2) Weight sweep (`2026-05-20_v423_weight_sweep`)

`w_topic ∈ {1.0, 0.95, 0.9, 0.85, 0.8, 0.75, 0.5}`, `w_flow = 1 −
w_topic`:

| w_topic | TIAGE | Dialseg711 | SuperDialseg | mean |
|---:|---:|---:|---:|---:|
| **1.00** (= v4.1.1) | 0.4675 | 0.5897 | **0.4631** | **0.5068** ⭐ |
| 0.95 | 0.4696 | **0.5923** ↑ | 0.4557 | 0.5059 |
| 0.90 | 0.4811 | 0.5879 | 0.4502 | 0.5064 |
| 0.85 | 0.4804 | 0.5835 | 0.4433 | 0.5024 |
| 0.80 | 0.4864 | 0.5755 | 0.4377 | 0.4999 |
| 0.75 | 0.4904 | 0.5666 | 0.4330 | 0.4966 |
| **0.50** | **0.4973** ↑ | 0.5156 | 0.4131 | 0.4754 |

**Per-dataset best weight**:
- TIAGE: w=0.50 → 0.4973 (**+2.98pp** vs v4.1.1)
- Dialseg711: w=0.95 → 0.5923 (**+0.26pp**, noise 범위 가능성)
- SuperDialseg: w=1.00 → 0.4631 (DSE 가 어떤 weight 든 해로움)

**Sanity check**: w_topic=1.0 의 Score (0.4675 / 0.5897 / 0.4631)
가 v4.1.1 공식 결과 (mpnet 단독) 와 정확히 일치 → v4.2.3 코드 구현
버그 없음 확정.

### 3) 진단 metric (`2026-05-20_v423_smoke`)

| dataset | n_trans | corr(z_t,z_f) | both_high | both_low | only_t | only_f | boundary_rate |
|---|---:|---:|---:|---:|---:|---:|---:|
| TIAGE | 1464 | 0.605 | 0.206 | 0.496 | 0.089 | 0.210 | 0.320 |
| Dialseg711 | 18639 | **0.765** | 0.252 | 0.487 | **0.027** | 0.234 | 0.354 |
| SuperDialseg | 16006 | 0.733 | 0.241 | 0.525 | 0.100 | 0.133 | 0.365 |

**해석**:
- TIAGE: corr 가장 낮음 (0.605), only_flow (0.210) > only_topic (0.089)
  → flow 가 *독자 boundary 신호* 많이 줌 → dual channel 가치 ✓
- Dialseg711: corr 가장 높음 (0.765), only_topic 거의 0 (0.027)
  → topic 만 단독 fire 거의 없음 = flow 가 topic 결정을 **희석**
  → dual 이 mpnet 단독보다 손해
- SuperDialseg: 중간 패턴, 결과상 mpnet 단독이 여전히 best

codex 예측 (2026-05-20) "mpnet·DSE noise correlation 높으면 dual channel
이 잘못된 방향으로 흔들기만 함" 이 정확히 실현. corr 0.7+ 대역에서 dual
이 손해.

## 판정

**v4.2.3-exp 는 default 승격 안 됨** (mean Score 0.4966~0.5068, v4.1.1
의 0.5068 못 넘김). dual channel 가설은 **부분 입증** (TIAGE +3pp 신호),
**부분 반증** (정형 topic-shift 셋에서 일관 손해).

→ **`exp` suffix 보존**, v4.1.1 = default. 도메인 특화 사용 가능
(`HiOnTopSegmenterV423Exp(w_topic=0.5)` 자연 대화용 variant 등). 향후
dataset-aware adaptive weighting 연구 (v4.2.4 후보) 의 baseline 으로
보존.

## SEM2 ablation table 비교 (참고)

본 v4.2.3-exp 가 dual encoder 도입의 **상한** 이 아님. 다음 ablation
들이 v4.2.4 / v4.x 의 후속 후보:

| 후보 | 변경점 | 가능성 |
|---|---|---|
| **adaptive weight** | confidence-aware `w(z_t, z_f)` — topic 확실할 땐 flow ↓, 불확실할 땐 ↑ | Dialseg711 손해 회복 + TIAGE 이득 유지 |
| **joint train calibration** | (m_topic, ρ_topic, a_topic, m_flow, ρ_flow, a_flow, w_topic) 전체 7D grid TIAGE-train sweep | smoke 의 channel-단독 best 가 dual joint optimal 가 아닐 수 있음 |
| **flow encoder 변경** | DSE-BERT → TOD-BERT-JNT-V1 (또는 CSM 학습 ckpt) | DSE 의 noise correlation 자체가 문제일 가능성 |
| **3-channel** | mpnet + DSE + TOD-BERT 셋 채널 | 채널 수 vs 평가 비용 trade-off |

## 한계 / 검증 미해결

- **TIAGE-test 의 +3pp 가 진짜 신호인지** seed variance 확인 필요
  (현재 seed=0 단일 run; v4.1.1 의 noise 범위 ±1pp 라 +3pp 는 통계적
  의미 가능성 높지만 multi-seed 미수행).
- **calibration overlap**: TIAGE-train 으로 δ\*_topic, δ\*_flow 둘 다
  fit. TIAGE-test 의 v4.2.3 결과는 in-domain 측정. transfer 측정은
  Dialseg711 / SuperDialseg 뿐. v4.1.1 결과 표의 TIAGE row 와 동일한
  disclosure 적용.
- **단일 weight 가정**: 모든 turn / 모든 도메인에서 같은 (w_topic,
  w_flow) 사용. adaptive weighting 미실험.
- **DSE 의 default pooling**: sentence-transformers 자동 wrapping
  mean-pool. CLS pooling 또는 다른 pool 시 결과 다를 가능성 (미실험).
- **DSE encoder 자체 약점 가능성**: dialseg711 / superseg 에서 mpnet
  대비 일관 손해 = DSE 가 dialogue flow encoder 로 약하다는 신호일 수
  있음. TOD-BERT-JNT-V1 등 다른 dialogue-tuned encoder 시도 필요.
- **`max_seq_length=512`**: 긴 발화 truncation 영향 미검증.
- **generic opener 등 발화 유형별 bucket 분석** 미수행 — codex risk
  list 의 false re-entry / noise correlation 깊이 추적은 본 smoke 범위
  밖.
