# v3.3.1 — Shared GRU event model + cosine prediction error (A+B 적용 후)

CLI method: `hi-ontop-full-v3.3.1`. Segmenter class: `HiOnTopSegmenterV331`.

## 한 줄

v3.2.1 의 prior 그대로. **likelihood 의 `μ_k` 를 RNN 예측 `ŝ_k` 로 교체** — SEM 본진의 *event-model + prediction error* 를 v3 라인에 부활. 2026-05-07 A+B 적용 후 **단일 공유 GRU + per-topic hidden state + predict caching** 구조로 운영.

## v3.2.1 대비 변경

| 축 | v3.2.1 | v3.3.1 |
|---|---|---|
| likelihood term | `τ · cos(s, μ_k)` | `τ · cos(s, ŝ_k)` |
| `ŝ_k` 출처 | (없음, μ_k 그대로) | per-topic GRU 예측 |
| topic state | centroid `μ_k` | `μ_k` + GRU `nn.Module` + Adam optimizer + 최근 `max_context` 임베딩 history |
| 학습 | 없음 | online SGD 1 step / assigned turn |
| sticky-CRP | `(C_k+1)^β + λ·stick` | 동일 |
| new cluster score | `τ · cos_threshold` | 동일 |

## Score 식

```
ê_n = argmax_k [ log[ (C_k + 1)^β + λ · 𝟙[e_{n-1}=k] ]  +  τ · cos(s, ŝ_k) ]
```

`ŝ_k` 는 topic k 의 GRU 가 예측한 *다음 embedding*:
```
ŝ_k = normalize( head( GRU( [s_{k,t-T+1}, ..., s_{k,t}] ) ) )
```
- `s_{k,*}` : topic k 에 누적 배정된 embedding sequence
- `T` ≤ `max_context` (default 8) : 가장 최근 T 개만 입력
- `head` : 32-D hidden → 768-D linear head
- 출력은 unit-norm 강제 → `cos(s, ŝ_k) ∈ [−1, 1]` 보장

## Topic state

코드: `src/hi_ontop/topic_v331_rnn.py` 의 `class TopicV33RNN`.

- `μ_k` : centroid (v3.1+ 와 동일, unit-norm 재정규화)
- `n_k` : sample count
- `h_k` ∈ ℝ^{hidden_dim} : 이 topic 의 GRU hidden state (2-D 텐서, `(1, hidden_dim)`)
- `_prev_h_in`, `_prev_x` : 직전 (h_in, x) 쌍. 다음 update 의 backprop 입력으로 쓰임
- `_cached_pred` : 직전 `update()` 시점에 계산한 unit-norm 예측 ŝ_k (numpy, `(dim,)`)

**모델/옵티마이저는 topic 외부에 위치**. Segmenter 가 단일 `EventRNN` + 단일 `Adam` 을 들고 있고, topic 은 생성 시 그 reference 를 주입받음. SEM2 의 "library of event models" 구조와 일치.

## Update rule

assignment 후 `topic.update(s)`:

1. **학습** (`_prev_h_in`, `_prev_x` 가 set 이고 `train_steps > 0` 이면):
   - `h_redo = model.step(_prev_x, _prev_h_in)` — 이전 transition 을 *현재 가중치* 로 재실행 (grad on)
   - `pred = model.predict(h_redo)`
   - `loss = 1 − cos(pred, s)`
   - backward → grad clip max-norm 1.0 → optimizer step
   - 이 backprop 은 cell 과 head 가중치 *모두* 를 업데이트 (`_prev_h_in` 만 leaf, 나머지 path 는 모델 파라미터 통과).
2. **상태 forward** (no grad):
   - `prev_h_in = h_k.clone()`, `prev_x = s_tensor.clone()` 저장 (다음 update 의 학습 입력).
   - `h_k_new = model.step(s, h_k)` — hidden 1-step.
   - `cached_pred_new = model.predict(h_k_new)` — 다음에 score 가 호출될 때 쓸 예측을 미리 계산.
3. `μ_k` Welford-style 업데이트 + unit-norm 재정규화.

**핵심**: scoring 단계 (`assign()` 내부 K topic loop) 는 RNN forward 를 호출하지 않음. `topic.log_likelihood(s) = dot(_cached_pred, s)` 만 — O(K) 메모리 접근.

## predict caching 의미

`_cached_pred` 는 *직전 update 시점의 model 가중치* 로 만들어진 값. 이후 다른 topic 이 update 되어 모델 가중치가 바뀌면 *원리상* stale. 다만:
- online SGD lr 작음 (default 1e-3) → 가중치 drift 작음.
- prediction 자체가 근사 (cosine surrogate) → 1-step weight drift 의 영향 < 모델/likelihood 자체의 inductive bias.
- 이 trade-off 가 *대신 K~50 RNN forward 를 매 turn 마다 0 으로 줄이는* 가속의 대가.

### Cold start

`n_k < min_rnn_history` (default 2) 인 동안에는 `predict_next()` 가 *centroid 그대로* 반환. → topic 이 충분히 자라기 전엔 v3.2.1 과 동일하게 동작. 무작위 RNN 초기화 출력으로 점수가 망가지지 않도록 가드.

## new cluster

`τ · cos_threshold` (v3.1 / v3.2 와 동일).

## 동기 (SEM 본진 복원)

v3.1.1 / v3.2.1 의 likelihood 는 *정적 centroid* 와의 cosine. SEM2 의 likelihood 는 *예측된 next embedding* 과의 prediction error. 즉 v3.x 라인은 SEM 의 핵심 메커니즘인 **scene dynamics** 를 빼고 있던 셈.

v3.3.1 은:
- topic 마다 작은 RNN 을 두어 "이 topic 이 다음에 어떤 embedding 을 낼지" 학습.
- likelihood 를 *prediction error 의 cosine 형태* 로 표현.
- 즉 SEM 본진의 prediction error 를 *cosine 거리 위에서* 복원.

**SEM 계승 원칙 (CLAUDE.md) 측면**: RNN event model 은 SEM 본진 메커니즘 → 새 component 가 아니라 *복원*. 정당화 부담 없음.

## SEM 계승 측면

- ✅ sticky-CRP prior, local MAP, online update : 그대로
- ✅ **scene dynamics (RNN event model)**: SEM 본진 복원 — v3.x 라인 최초.
- ⚠️ likelihood 형태: SEM 본진은 Gaussian PE, v3.3.1 은 cosine PE. cosine substitution 은 SEM2 가 metric 대용으로 허용한 변형. axiomatic 보장은 약화 (`context/sem-equations.md` 의 cosine substitution 절 참조).
- ❌ `f0` (event-start initial condition): 여전히 미포팅. cold-start 는 centroid fallback 으로 우회.
- ❌ restart-vs-repeat halving: 미포팅 (v1 와 동일).

## 알려진 한계 / 비용

1. **CPU bound** (`torch.cuda` driver 구식 — repo 환경) → 순수 CPU. A+B 적용 후에도 GRU forward/backward 자체는 CPU.
2. **Cached prediction staleness**: 위 § "predict caching 의미" 참조. 실용상 영향 작음.
3. **Cold start 짧음**: `min_rnn_history=2` 는 너무 빠르게 RNN 사용. 작은 history 로 학습된 RNN 예측이 centroid 보다 나쁠 수 있음 — RNN 켜는 시점 ablation 필요.
4. **RNN 학습 안정성**: gradient clip 만 있고 weight regularization 없음. long conv 에서 drift / divergence 가능성.

## 고려 중인 변형 (작은 변경 누적)

이 섹션은 *적용되지 않은* 후보를 적어두는 용도. 적용되면 "변경 이력" 으로 옮기거나 새 버전으로 분리.

### C. Lazy training (1.5–2× 가속)
- 매 turn 1 SGD step → N turn 마다 mini-batch 1 step.
- training 빈도 줄여 stability 도 도모.
- 상태: 미고려.

### D. Per-topic concentration κ_k (vMF 도입)
- centroid + GRU 외에 per-topic *분산성* 을 학습.
- vMF likelihood 로 갈아타면 `κ_k` 가 등장 — concentration 학습 = 분산성 학습.
- **SEM 본진엔 없음**. 도입하려면 CLAUDE.md "SEM 계승 원칙" 의 정당화 3 단계 통과 필요.
- 상태: 미고려, 위 정당화가 선행 필요.

### E. RNN 학습 weight decay / 정규화
- 현재 grad clip 만. long conv 에서 가중치 drift / 폭주 가능성.
- AdamW + weight decay 1e-4 등 도입 후보.
- 상태: 미고려.

## 변경 이력

- **2026-05-07 v0**: 도입 (codex 위임 구현 + 자체 검증). per-topic GRU instance + per-topic Adam optimizer + `max_context` deque history. 사유: SEM 본진의 scene dynamics + prediction error 를 v3 라인에 복원.
- **2026-05-07 A+B 적용 (v3.3.1 그대로 유지, 알고리즘 의미 동등)**:
  - **A — predict caching**: 매 score 호출마다 RNN forward 하던 것을 `update()` 시점에 한 번 계산해 `_cached_pred` 로 저장. score 는 cosine dot 만. 매 turn O(K) RNN forward → 0.
  - **B — shared GRU + per-topic hidden state**: per-topic `nn.Module` 인스턴스 폐기. segmenter 가 단일 `EventRNN` + 단일 `Adam` 을 보유. topic 은 `h_k ∈ ℝ^{hidden_dim}` 만. SEM2 `event_models.py` 의 실제 구조와 일치.
  - 학습 정확성 보존 위해 topic 이 `(_prev_h_in, _prev_x)` 한 쌍을 들고 다님 → 다음 update 시 현재 가중치로 transition 을 재실행, cell+head 모두 backprop.
  - 결과: 한 run 이 ~60분 → ~수분 수준의 latency 단축 (실측 sweep 결과로 갱신 예정).
  - 의미상의 변경 없음 — sticky-CRP prior, likelihood 형태, fresh-cluster 점수 모두 동일.
- **`max_context` 의 운명**: A+B 후엔 사용 안 함. CLI / segmenter 인자로는 backward compat 위해 받지만 무시. 다음 메이저 정리 때 제거 후보.
