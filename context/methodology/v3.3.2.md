## 동기

v3.3.1 의 default sweep 에서 600-turn mega-topic 이 깨지지 않은 직접적 원인 (`methodology/v3.3.1.md` "알려진 한계" 참조):

- mega-topic 의 prior `log[(601)^0.5 + 10] ≈ 3.54` + RNN 이 학습한 *bulk direction* 의 `τ·cos ≈ 31~40` 이 fresh cluster 의 `τ·cos_threshold = 35` 를 *MAP 산수상* 으로 흡수.
- 즉 *MAP 평균적으로* 는 mega 가 이김. 새 turn 의 의미가 크게 shift 했어도 MAP 식 안에서는 prior + likelihood 균형으로 묻힘.

SEM2 본진은 *Bayesian surprise spike* 가 발생하면 MAP 결과와 *별개로* 새 event 시작:

> "When the prediction error against the current event is large, restart."

v3.3.2 는 그 메커니즘을 단순 한 줄 규칙으로 복원.

## Score / Boundary 규칙

```
log_score_k = log[(C_k + 1)^β + λ · 𝟙[prev=k]] + τ · cos(s, ŝ_k)
             (k ≤ K)
log_score_{K+1} = log α + τ · cos_threshold
             (fresh cluster)
```

- `MAP 후보 = argmax_k log_score_k` (v3.3.1 경로)
- **Surprise rule (v3.3.2 추가)**: `max_{k ≤ K} cos(s, ŝ_k) < (1 − pe_threshold)` 면 MAP 무시하고 K+1 (fresh) slot 으로 강제.
  - 의미: "어느 topic 도 이 새 turn 을 잘 예측 못함 (PE 가 모두 큼)" → 새 event.

`pe_threshold = 1.0` (default) 이면 조건이 `max_cos < 0` 가 되어 거의 발동 안 함 → v3.3.2 ≡ v3.3.1.
`pe_threshold = 0.5` (권장 시작값) 이면 `max_cos < 0.5` 일 때 강제 boundary.
`pe_threshold = 0.0` 면 `max_cos < 1.0` 일 때 → 사실상 매 turn 강제 boundary (over-split). 디버그/단위테스트용.

## 새 cluster 점수와의 관계

`new_cluster_score = τ · cos_threshold = 35 (default)`. surprise rule 은 *prior 무관* 이라 mega 의 거대 prior bonus 를 우회. 그래서 mega 가 "MAP 산수로는 이기지만 surprise 로는 진다" 가 가능.

수식적으로:
- MAP 만 있는 v3.3.1: mega 흡수 vs fresh = `prior_mega + τ·cos_mega vs τ·cos_threshold`
- v3.3.2: `(MAP 결과 후보 → fresh)` if `max_cos < 1 − pe_threshold`, 즉 `min_PE > pe_threshold`.

## SEM 계승 측면

- ✅ sticky-CRP prior, local MAP, online update : 그대로
- ✅ shared GRU dynamics + per-topic hidden state : v3.3.1 그대로
- ✅ **surprise → boundary**: SEM 본진 메커니즘 *복원*. 즉 새 component 가 아니라 SEM 에서 빠져 있던 mechanism 을 가져옴.
- ⚠️ `pe_threshold` 는 SEM 본진의 *암시적* 메커니즘에 명시적 hyperparameter 를 부여한 것. SEM2 가 surprise 강도를 *Gaussian likelihood 의 분산* 으로 implicitly 다뤘다면, v3.3.2 는 cosine surrogate 위에서 explicit threshold 로 다룸.

→ CLAUDE.md "SEM 계승 원칙" 의 정당화 3 단계:
1. **SEM 에 왜 있나**: 없는 게 아니라 *암시적으로 있음*. SEM2 의 prediction-error 기반 likelihood 는 surprise spike 시 이미 새 event 를 favor. v3.3.1 cosine substitution 으로 가는 길에서 *implicit ↔ explicit* 변환 단계로 v3.3.2 가 등장.
2. **충돌 안 함**: cosine 거리 위 explicit rule 이 본진 Gaussian 의 implicit surprise 와 같은 효과를 냄. sCRP / Bayes / local MAP / scene dynamics 와 모두 직교.
3. **decision-log 기록**: 본 파일 + `context/06-decision-log.md` 2026-05-08 entry.

## 알려진 한계

1. **`pe_threshold` global 고정**: 데이터셋·embedding 모델 마다 cosine 분포가 다른데 단일 값으로 결정. v3.1.1 의 `cos_threshold` 한계와 같은 패턴.
2. **`max` 만 보고 결정**: K 개 topic 중 하나라도 `cos > 1−pe_threshold` 면 surprise OFF. 단일 outlier topic 이 surprise rule 을 무력화 가능. (mitigation: 전부 mega 인 경우엔 outlier topic 자체가 mega 라 발동 안 하는 게 의도일 수도)
3. **MAP 자체와의 정합성**: surprise 발동시 MAP 결과를 무시 → 그 turn 은 *prior 와 likelihood 모두* 의 정상 의사결정 외부에서 처리됨. 이는 SEM2 의 spirit 과는 일치 (restart 는 본디 MAP 외부 mechanism) 하지만, 이론적 일관성 측면에선 거친 합성.

## 고려 중인 변형

### F. Per-topic / per-conversation `pe_threshold` adaptive
- 최근 cos 분포에서 임계값 자동 추정. v3.1.1 의 `cos_threshold` 도 같은 변형 후보. 통합 가능.
- 상태: 미적용.

### G. Probabilistic surprise (soft)
- 현재 hard rule. soft 버전: `P(new) = σ(α·(threshold − max_cos))` 로 확률화.
- 좀 더 SEM 본진의 Bayesian 정신과 일치. 다만 stochastic 요소 도입.
- 상태: 미적용.

### H. Surprise event 의 *취소* (rollback)
- surprise 발동 후 다음 turn 이 다시 high cos 이면 *방금 만든 topic 을 폐기* + 원래 topic 으로 복원. 단발성 outlier 흡수.
- 상태: 미고려, SEM 본진엔 없음.
