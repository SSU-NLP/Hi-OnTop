## 0. 30초 요약

- **과제**: 여러 화제가 섞인 대화에서 "화제가 바뀌는 지점(topic
  boundary)"을 자동으로 찾는다 = **Dialogue Topic Segmentation (DTS)**.
- **우리 계보**: Hi-OnTop 은 인지과학 모델 **SEM**(Structured Event
  Memory) 계승. SEM 은 "다음 발화를 예측하다가 예측이 크게 빗나가면
  거기서 사건(topic)이 바뀐 것" 으로 본다.
- **반전의 발견**: SEM 의 학습형 예측기(RNN)가 오히려 신호를 죽이고
  있었고, "직전 발화와 얼마나 다른가(prev-cos)" 라는 1줄짜리 규칙이
  더 나았다. 알고 보니 그 1줄이 **SEM 의 가장 단순한 형태(identity
  dynamics)** 였다.
- **v4.1.1**: 그 통찰을 정식 복원(v3.3.9)한 뒤, "직전 *한* 발화"
  대신 "최근 몇 발화의 맥락"과 비교(**causal-window**)하도록 확장한
  버전. 표준 벤치마크(SuperDialseg·Dialseg711)에서 직전 버전보다
  일관되게 낫다.

## 1. 문제 정의 — DTS 가 뭔가

대화는 turn(발화) 의 연속이다. 사람들은 한 화제로 몇 turn 얘기하다
다른 화제로 넘어간다. **DTS = 각 turn 경계가 "같은 화제 계속" 인지
"새 화제 시작" 인지 판정**.

예 (TIAGE):
```
t4 i am currently building a tree house in my spare time   (화제 A)
t5 do you have any kids? i would love a tree house for kids (← 화제 전환?)
```
GT(정답) 라벨은 각 turn 에 "여기서 화제 바뀜=1 / 아님=0".

**왜 어려운가**: 같은 화제 안에서도 표현이 많이 바뀌고(잡담),
화제가 바뀌어도 단어가 비슷할 수 있다. 표면 유사도 ≠ 화제 경계.

이 프로젝트의 평가용 데이터셋 3종 (성격이 매우 다름 — 중요):
| 벤치 | 성격 | turn/dial | 경계율 | 난이도 |
|---|---|---:|---:|---|
| **TIAGE** | 사람 잡담(PersonaChat) | ~15 | ~0.22 | 매우 어려움(잡담 노이즈) |
| **SuperDialseg** | 문서기반 상담 대화 | ~13 | ~0.23 | 중간 |
| **Dialseg711** | 합성(서로 다른 대화 이어붙임) | ~27 | ~0.14 | 쉬움(경계 의미 선명) |

## 2. 평가 지표 — 각각 무엇을, 왜

세그멘테이션은 "경계 위치"가 핵심이라 일반 분류 지표만으론 부족하다.

- **F1↑** (boundary F1): 경계를 *정확히 그 자리*에서 맞췄나. 단점:
  매 turn 다 경계라고 찍으면 recall=1 로 부풀려짐(**과분절에
  취약/게임됨**).
- **Pk↓**: 길이 k 윈도우를 슬라이딩하며 "양 끝이 같은 segment 인가"
  를 GT 와 비교, 불일치율. near-miss 를 부분 인정. 낮을수록 좋음.
- **WD↓ (WindowDiff)**: Pk 변형, 윈도우 안 경계 *개수* 차이. 경계
  과다/과소에 민감. 낮을수록 좋음.
- **ARI↑** (Adjusted Rand Index): 경계가 아니라 "turn 들을 같은
  화제로 묶은 분할" 전체가 GT 분할과 얼마나 일치하나(우연 보정).
  과분절·과병합·붕괴 동시 페널티. 내부 가드(F1 게임 탐지)용.
- **Score↑** (SuperDialseg 공식 종합): `0.5·F1 + 0.25·(1−Pk) +
  0.25·(1−WD)`. 문헌 leaderboard 비교용 단일 수치.

판정 기준 변천: 처음 ARI-primary(F1 게임 방지) → 2026-05-18
사용자 결정으로 **target = WD/F1/Pk(+Score)** (문헌 비교 위해), 단
ARI/n_topics/collapse 는 **가드 컬럼으로 존치**(F1 게임·붕괴 재발 방지).

## 3. 계보 — SEM 에서 v4.1.1 까지 (왜 이렇게 됐나)

### 3.1 SEM 계승 원칙 (프로젝트 최상위 제약)
Hi-OnTop 은 SEM/SEM2 계승. SEM 핵심: scene(상황)을 잠재 event 로 보고,
event 별 **dynamics 예측기 f** 가 다음 scene 을 예측, **예측오차(PE)가
크면 event(topic) 경계**. 군집은 sticky-CRP(이전 topic 에 가중)로
관리, 매 turn local MAP 로 topic 배정. **SEM 에 없는 메커니즘은
근거 없이 도입 안 함**(query-cosine retrieval 금지 등).

### 3.2 v3.3.x — RNN scene-dynamics 복원 시도
f 를 per-topic GRU(EventRNN)로 학습. v3.3.5~3.3.8 여러 변형.
**문제 발견 (η-ablation, failure dump)**:
- TIAGE 한 topic ≈ 3턴 → RNN 학습 샘플 ~3개 = **구조적 데이터 기근**.
  RNN 은 학습이 안 되고, 매 턴 forward/train 하지만 결과는 거의
  안 쓰이거나(게이트) 해롭다.
- η-ablation: δ_eff² = η·δ_prev² + (1−η)·δ_model²(δ_model=RNN). η
  를 1→0 으로(RNN 비중↑) 모든 지표 단조 악화. **η=1(RNN 완전 미사용)
  이 best.**

### 3.3 결정적 진단 — 1줄 baseline 이 SEM 전부를 이김
같은 인코더·같은 평가에서 **"직전 발화와 cosine 거리 > θ → 경계"**
라는 1줄 규칙(prev-cos)이 F1 ≈ 0.44, 우리 SEM 전 변형(0.25~0.36)을
압도. 인코더·평가정의 무관(3개 인코더 동일).
→ codex 진단: prev-cos 는 *SEM 밖 heuristic 이 아니라* **SEM2 의
학습 전 cold-start dynamics(f(x)=x_prev, identity)의 PE 그 자체**.
SEM 이 못 살린 이유 = fresh/untrained baseline `L0` 오보정 +
scalar cosine-PE 의 σ² 포화 (RNN 아키텍처 문제 아님).

### 3.4 v3.3.9 — prev-cos 를 SEM 정합으로 정식 복원
- repeat(같은 topic) likelihood 를 δ_prev 기반으로, **prior-corrected
  fresh baseline** `B0_t = Lδ(δ*) + log(P_prev/P_new)` 도입 →
  sCRP prior 항이 상쇄되어 "repeat vs new" 결정이 매 turn **정확히
  `δ_prev < δ*`** 와 동치(δ*=경계 임계값).
- σδ² 는 고정 `c·δ*²`(온라인 분산추정 폐기 — 그게 v3.3.9 초기
  회귀 원인이었음). δ* 는 **TIAGE train**에서 추정(test 누설 없음).
- 결과: TIAGE test 13-method 중 ARI·F1·Pk 동시 best (F1 0.437 ≈
  prev-cos 동급 회복). RNN 코드는 `use_rnn` 플래그로 보존, η=1 자동
  skip(연산 ~4배 절감, 결과 불변).

### 3.5 v4.1.1 (구 v3.3.10) — causal-window
v3.3.9 의 약점: "직전 *한* 발화"만 보면 잡담의 turn 단위 노이즈에
가짜 경계(FP) 남발 (TIAGE failure dump: FP 393 vs FN 117).
**해결**: 비교 대상을 단일 발화 → **최근 m 발화의 감쇠가중 맥락**:
```
δ_prev = 1 − cos(s_{t-1}, s_t)
c_{t-1} = normalize(Σ_{i=1..m} ρ^{i-1}·s_{t-i})   # 과거만(causal)
δ_ctx  = 1 − cos(c_{t-1}, s_t)
δ_adj  = a·δ_prev + (1−a)·δ_ctx
δ_eff² = η·δ_adj² + (1−η)·δ_model²   # η=1 기본 → δ_eff=δ_adj
```
"causal" = 미래 turn 안 봄(온라인 segmentation, lookahead 금지) —
양방향 TextTiling 과 구분. 윈도우가 단일 turn 노이즈를 평활 → FP↓.
SEM 계승상: SEM 의 f(x_{1:n})(history-conditioned)을 v3.3.9 가
1-step 으로 축약한 걸 history 더 쓰도록 되돌린 근사 — 새 메커니즘 아님.

### 3.6 왜 v3.3.10 → v4.1.1 (메이저 버전업)
v3.3.x = "RNN scene-dynamics 복원" 정체성. 그런데 결론은 RNN 버리고
identity+calibrated-MAP. 그건 v3.3.x 와 질적으로 다른 라인이라
**메이저 분리**(사용자 결정 2026-05-18). RNN 은 제거가 아니라
`use_rnn` 플래그로 보존(η<1 시 사용 가능).

## 4. 결과 (공식 SuperDialseg metric, literature-comparable)

### 4.1 TIAGE test (잡담형, 어려움)
v3.3.9 가 13-method 중 ARI 0.408/F1 0.437/Pk 0.415 동시 best.
causal-window 는 TIAGE-train 에선 +0.006(노이즈) — **잡담 특유의
가림**(아래 표준벤치에서 가치 드러남).

### 4.2 표준 벤치 (Score↑/F1↑/Pk↓/WD↓; zero-shot = TIAGE 전이, 튜닝 0)
| 벤치 | method | Score | F1 | Pk | WD |
|---|---|---:|---:|---:|---:|
| SuperDialseg | prev-cos@oracle(천장) | 0.447 | 0.458 | 0.467 | 0.660 |
| SuperDialseg | v3.3.9 @TIAGE-δ* | 0.460 | 0.449 | 0.468 | 0.589 |
| SuperDialseg | **v4.1.1 @TIAGE-cfg** | **0.463** | 0.432 | 0.471 | **0.541** |
| Dialseg711 | prev-cos@oracle(천장) | 0.590 | 0.536 | 0.322 | 0.389 |
| Dialseg711 | v3.3.9 @TIAGE-δ* | 0.514 | 0.492 | 0.394 | 0.534 |
| Dialseg711 | **v4.1.1 @TIAGE-cfg** | **0.590** | **0.549** | 0.325 | 0.415 |
| Dialseg711 | v4.1.1 @oracle-δ*(상한) | 0.629 | 0.560 | 0.285 | 0.319 |

**해석**:
- v4.1.1 이 두 표준벤치에서 v3.3.9 를 일관 상회(Score·WD). Dialseg711
  zero-shot 은 **튜닝 0 으로 유사도 천장(Score 0.590) 매칭**, v3.3.9
  대비 +0.076. → causal-window 가치가 표준벤치에서 입증.
- F1 은 SuperDialseg 에서 v3.3.9 가 약간 높음(경계 덜 찍어 recall↓
  ↔ WD/Score↑). "이긴다"는 지표 의존(Score 종합 기준 v4.1.1).
- 유사도 방법의 천장: SuperDialseg ≈ F1 0.46(잡담형이라 낮음),
  Dialseg711 ≈ 0.54(합성·경계 선명). **벤치마다 천장이 다르다.**

## 5. 한계 / 검증 미해결 (정직 기록, 제거 금지)

1. **δ\* 가 TIAGE-train 전이값**. SuperDialseg/Dialseg711 은 zero-shot.
   SuperDialseg validation 으로 δ\* 재calibration 시 향상 여지(특히
   SuperDialseg) — **진행 예정, 미완**.
2. **문헌/SOTA 0.55~0.65 의 출처·split·supervised 여부·인코더 미확정**
   → 외부 초과 주장 금지. oracle-δ\* 행은 test 에 맞춘 *상한*이라
   외부 비교 불가(정직값은 zero-shot).
3. 인코더 = `multi-qa-mpnet-base-dot-v1` (MPNet 백본, QA-검색용
   비대칭). 문헌 인코더 정합 ablation 미실행. (단 진단상 TIAGE 에선
   인코더가 병목 아님 — 3개 인코더 동등.)
4. FN(화제 바뀌었는데 표현 유사, 예 δ≈0.13)은 어떤 임계값·윈도우로도
   원천 회복 불가 = 구조적 한계.
5. F1 vs WD trade-off 가 벤치별로 다름 — 단일 우열 단정 금지.
6. RNN 영구 제거 아님(보존). "learned-f 본질 무용" 결론은 model-
   calibrated fair ablation 후로 보류(현 η-ablation 은 prev-cos
   척도로 RNN 채점한 confound 존재).
